# Вектор — фронтенд

Электронный дневник и журнал для школ: ученик, родитель, учитель,
администратор. Чистые HTML, CSS и ES-модули, без сборки и npm.
Без токена приложение работает на демо-данных из `localStorage`; после входа
через API показывает данные бэкенда.

## Запуск

Нужен статический сервер — ES-модули не грузятся из `file://`.

```bash
cd frontend
python -m http.server 5173
```

Откройте http://localhost:5173. На Windows: `Запустить.cmd`, остановка —
`Остановить.cmd`.

Вход — кнопки «Демо-доступ» (без сервера) или настоящий аккаунт: логин и
пароль, код из MAX-бота, либо Яндекс ID. Демо-логины: `belov.artem`,
`belova.anna`, `ivanova.maria`, `kuznetsova.elena`.

## Как устроено

- Один документ `index.html`; навигация — по хешу (`#/home`, `#/diary`,
  `#/journal/...`). Серверу не нужны отдельные маршруты.
- `main.js` выбирает экран по адресу и роли, вставляет HTML и вызывает
  `mount(root)` для обработчиков.
- Каждый экран — функция `xxxView({ params, path, go, rerender })`, которая
  возвращает `{ html, mount, captureDraft?, restoreDraft? }`.
- `store.js` — граница работы с данными. Демо-данные подключаются из
  `data.js`, `teacher-data.js`, `admin-data.js`. Для сервера меняется этот
  слой; список операций — в разделе «Сервер».
- Состояние хранится в `localStorage` под ключом `vector-demo-v1`.
- Роли: `student`, `parent`, `teacher`, `admin`. Родитель видит данные
  ребёнка и не имеет права писать; маршруты и меню — в начале `main.js`.
- HTML-фрагменты именованные: `<!-- fragment:имя -->` … `<!-- /fragment:имя -->`.
  В JS — `fragment('экран', 'имя', [значения])`, подстановки `{{0}}`, `{{1}}`.
  Пользовательский текст всегда проходит через `esc()`.

## Роли и экраны

| Роль | Экраны |
|---|---|
| Ученик | главная, дневник, оценки и предмет, почта, ИИ |
| Родитель | те же экраны ученика; переключатель ребёнка, только чтение |
| Учитель | главная, журнал и анализ, мой класс, почта |
| Администратор | главная, классы, учителя, расписание, пропуски, почта |

Общее для всех — вход и настройки (тема, акцент, профиль, пароль).

## Демо-бот MAX

Симуляция бота и кнопки «Демо-доступ» нужны только для показа без сервера:
`js/demo-bot.js`, `css/demo-bot.css`, `html/demo-bot.html`. Экран входа
работает и без них (логин + пароль или логин + код из MAX). Чтобы убрать:

1. удалить три файла `demo-bot.*`;
2. строку `import './demo-bot.js';` в `js/main.js`;
3. ссылку `css/demo-bot.css` в `index.html`;
4. `"demo-bot"` из `html/manifest.json`.

Функции `store.js`, которыми пользуется бот: `redeemInvitation`,
`requestLoginCode`, `verifyLoginCode`, `checkLogin` — это контракт для
сервера и бота. `botAccount`, `selectDemoMaxProfile`, `botSetPassword` нужны
только демо-боту.

## Сервер

Токен хранится в `localStorage` под ключом `vector-token`. При загрузке
`main.js` вызывает `store.bootstrap()`: если токен есть, `GET /api/users/me`
поднимает сессию, иначе остаётся демо-режим.

Вход:

- логин + пароль — `POST /api/users/login` (форма, как у OAuth2);
- код из MAX — `POST /api/users/auth/max-code`; код выдаёт бот командой
  `/code` или кнопкой «Вход на сайт» (10 минут, одноразовый);
- Яндекс — редирект на `/api/auth/yandex/login-url`, токен кладёт callback.

Что уже читается с сервера:

- профиль и роль — `/api/users/me`;
- дети родителя — `/api/users/me/children`;
- оценки, задания, расписание — `/api/grades/my`, `/api/tasks`,
  `/api/schedule/my` (и `/child/{id}` для родителя);
- классы и ученики учителя — `/api/classes`, `/api/classes/{id}/overview`;
- журнал учителя — `/api/journal` (уроки, оценки, «Н», итоговые);
- почта — `/api/messages` (входящие, отправленные, прочтение, вложения);
- посещаемость — `/api/attendance/class/{id}`;
- расписание класса — `/api/schedule/class/{id}`;
- настройки школы — `/api/school/settings`;
- профиль, аватар и пароль — `PATCH /api/users/me`,
  `POST /api/users/me/change-password`;
- привязка родителя — `POST /api/users/me/parent-link-token` (код ученика)
  и `POST /api/users/me/link-parent` (родитель вводит код);
- классы и учителя администратора — `/api/admin/*`;
- уведомления — `/api/notifications`;
- «Вектор ИИ» — `/api/ai/chat` (если Ollama недоступна, экран отвечает
  локальными подсказками).

Отметка «сделано» у домашнего задания вызывает `POST /api/tasks/{id}/complete`.

В серверном режиме админка управляет классами и учителями через API:
создание и удаление класса, смена классного руководителя, добавление и
удаление ученика, одноразовый код для учителя, предмет и деактивация
учителя. Родителей и учеников создаёт бот по кодам, поэтому «приглашения»
на экране классов — это код класса, а не отдельные карточки.

При локальной разработке страницу отдаёт `http.server` на 5173, а API —
uvicorn на 8000; `api.js` сам подставляет `http://127.0.0.1:8000`. В проде
запросы идут на тот же origin.

## Дизайн

- Две темы (`light`/`dark`) и пять акцентов; палитры — `css/palettes.css`,
  применение — атрибуты `data-theme`, `data-accent` на `<html>`, без
  inline-цветов.
- Токены (цвета, отступы, радиусы, тени) — в начале `css/app.css`.
- Мобильный экран — по умолчанию, компьютер — `@media (min-width: 1024px)`.
- Шрифт Inter, язык `ru-RU`, тексты интерфейса на русском.
- Иконки — инлайн-SVG из `ui.js`, внешних иконочных шрифтов нет.

## Третьи стороны

- Генератор QR `js/vendor/qr/` (Kazuhiko Arase, MIT) — лицензия в
  `js/vendor/qr/LICENSE`. Используется для приглашений.
- Google Fonts (Inter) подключается с CDN в `index.html`.

## Что в демо ненастоящее

- Без входа данные и «сегодня» фиксированы (среда, 21 октября 2026, 9:12) —
  `data.js`; после входа дата берётся системная, а данные — из API.
- Код MAX в демо-боте создаётся в браузере и показывается на экране.
- «Вектор ИИ» в демо отвечает по шаблонам на данных браузера; на сервере —
  настоящая Ollama, а без неё экран снова отвечает подсказками.
- Уведомления, вложения, настройки школы и админка классов/учителей в демо
  работают на данных браузера, на сервере — через API.

## Правки экранов

Например, журнал: `html/journal.html`, `css/journal.css`, `js/journal.js`.
HTML — фрагменты между комментариями `fragment:имя`, подстановки — `{{0}}`.
Список шаблонов — `html/manifest.json`; новый экран нужно добавить туда, в
`ROUTES` в `js/main.js` и подключить CSS в `index.html`.

## Ограничения

- Нет сборки и типов; для продакшена разумно перейти на Vite + TypeScript.
- `store.js` большой: при подключении сервера стоит разделить его на
  auth, diary, journal, admin, mail.
- Разметка собирается строками, местами с inline-`style`.
- Пароли и коды в демо хранятся в браузере; настоящие пароли не используйте.
